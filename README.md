# 東方人気投票ブラックジャック

第22回東方Project人気投票の**順位をそのまま点数**にして、**目標の点数を超えずに、ぴったりを目指す**、2〜5人用のWebゲームです。
目標の点数は難易度で変わります（Hard は21、Lunatic は150）。
スマートフォンのブラウザで、同じルームに入って遊びます。

> ※本ゲームは東方Projectのファン制作（非公式）ゲームです。原作者・公式とは関係ありません。

## 1. 遊び方（ルール）

ゲームを始める前に、ホストが**難易度**を選びます。選んだ難易度は、参加者全員の画面に表示されます。

| 難易度 | 使えるキャラクター | 目標値 | ターン |
|---|---|---:|---:|
| Easy | （Coming Soon） | ― | ― |
| Normal | （Coming Soon） | ― | ― |
| **Hard** | 人気投票 1〜50位の50人 | **21** | 5 |
| **Lunatic** | 全キャラクター（225人） | **150** | 5 |

どの難易度でも、次の流れは同じです。

1. 毎ターン、全員が東方キャラクターを**1人**選びます。
   一覧は**50音順**に並んでいて、名前でも、よみがな（例：れいむ）でも検索できます。
   （Hard では、一覧にも検索結果にも、50位以内のキャラクターしか出てきません）
2. そのキャラの人気投票の**順位**が、そのまま点数に加算されます。（例：10位のキャラクターなら +10）
3. **選ぶときには、順位もポイントも表示されません。**
   全員が決定すると、選択と順位が**一斉に公開**されます。（それまで他の人の選択も見えません）
4. 同じターンに同じキャラを選んだ人が2人以上いたら、その全員が **+0**。
   そのキャラは、以降のターンでは**だれも選べなくなります**。
5. 合計が**目標値を超えたら OUT**。ちょうどはセーフ（Hard なら21、Lunatic なら150）。OUTの人は以降のターンを観戦します。
6. **5ターン**終了時、OUTでない人のうち目標値に最も近い人が勝ち。同じ点数なら全員が勝者です。

## 2. まず動かしてみる（お試しモード）

Firebase の設定をしなくても、**1台のPCのブラウザで、タブを複数開いて**ゲームの流れを確認できます。

1. `start-local.bat` をダブルクリックします。（黒い画面が開き、ブラウザで `http://localhost:8000/` が開きます）
   - 動かないときは、このフォルダでコマンド `python tools/serve.py` を実行してください。
2. 「ルームを作成」→ 名前を入れて作成すると、ルームIDが表示されます。
   - 名前の欄には、最初から「霊夢」が入っています。そのままでも、書き換えても構いません。
3. ブラウザで**新しいタブ**を開き、同じ `http://localhost:8000/` を開いて「ルームに参加」→ ルームIDを入力します。
   - タブ1つが、プレイヤー1人になります。
4. 最初のタブ（ホスト）で、難易度（Hard か Lunatic）を選んで「ゲーム開始」を押します。

待機画面の「最初の画面に戻る」を押すと、ルームから退出して最初の画面に戻れます。

画面の一番上に黄色い帯「お試しモード」が出ているあいだは、このモードです。
**別の端末（スマホ同士など）とはつながりません。** つなげるには次の手順に進みます。

> `index.html` をダブルクリックして開いても動きません。必ず `http://localhost:8000/` から開いてください。

## 3. スマホ同士で遊べるようにする（公開の手順）

やることは3つです。どれも無料でできます。

| | やること | 目的 |
|---|---|---|
| 手順A | Firebase を準備する | スマホ同士でデータをやり取りする場所を作る |
| 手順B | PCで動作を確認する | 公開前に、Firebase につながるか確かめる |
| 手順C | GitHub Pages で公開する | スマホから開けるURLを作る |

### 手順A：Firebase の準備（10分ほど）

1. <https://console.firebase.google.com/> を開き、Googleアカウントでログインします。
2. 「プロジェクトを作成」を押します。
   - 名前は自由です（例：`touhou-blackjack`）。
   - Googleアナリティクスは「無効」で構いません。
3. **Realtime Database を作ります。**
   - 左のメニュー「構築」→「Realtime Database」→「データベースを作成」
   - ロケーションは「シンガポール (asia-southeast1)」がおすすめです（日本から一番近い）。
   - 「ロックモードで開始」を選んで有効にします。
4. **セキュリティルールを貼り付けます。**
   - Realtime Database の画面で「ルール」タブを開きます。
   - 入っている文字をすべて消し、[database.rules.json](database.rules.json) の中身をすべてコピーして貼り付けます。
   - 「公開」を押します。
5. **匿名認証を有効にします。**
   - 左のメニュー「構築」→「Authentication」→「始める」
   - 「Sign-in method」（ログイン方法）→「匿名」→ 有効にして保存します。
6. **接続情報を取得します。**
   - 左上の歯車 →「プロジェクトの設定」→ 下のほうの「マイアプリ」→ `</>`（ウェブ）のアイコン
   - アプリのニックネームを入れて「アプリを登録」（Firebase Hosting のチェックは不要）
   - 表示される `const firebaseConfig = { … }` の中身を控えます。
7. **[js/firebase-config.js](js/firebase-config.js) に貼り付けます。**
   - それぞれの `''` の中に、対応する値を入れて保存します。
   - `databaseURL` が入っているか確認してください。表示されていない場合は、Realtime Database の「データ」タブの上部にあるURL（`https://～.firebasedatabase.app`）を入れます。

> **apiKey を公開して大丈夫？**
> Firebase のウェブ用の apiKey は「どのプロジェクトか」を示す識別用の情報で、秘密の鍵ではありません。
> データを守っているのは手順4のセキュリティルールです。
>
> GitHub に公開すると、「APIキーが公開されています」という内容の警告メールが GitHub や Google から届くことがあります。
> ウェブ用の apiKey はもともと利用者のブラウザに配られるものなので、このゲームの使い方であれば問題ありません。
> 気になる場合は、Google Cloud コンソールの「認証情報」でこのキーに「HTTP リファラー」の制限をかけ、
> 自分の公開URL（`https://（ユーザー名）.github.io/*`）と、PCでの確認用の `http://localhost:8000/*`・`http://127.0.0.1:8000/*` だけを許可できます。

### 手順B：PCで動作を確認する

1. `start-local.bat` で開き直します。
2. **黄色い帯「お試しモード」が消えていれば**、Firebase につながっています。
3. 2人目として参加するときは、次のどれかの方法で開きます。
   - 新しいタブで `http://127.0.0.1:8000/` を開く
     （`localhost` と `127.0.0.1` は同じPCを指しますが、ブラウザからは別のサイトに見えるので、別の人として扱われます）
   - シークレットウィンドウで開く
   - 別のブラウザ（Chrome と Edge など）で開く

   Firebase を使うモードでは、同じアドレスを開いたタブ同士は「同じ人」として扱われるためです。
4. ルーム作成 → 参加 → ゲーム開始 → 1ターン進む、まで確認できればOKです。

> Firebase を設定したあとでお試しモードを使いたいときは、URLの末尾に `?demo` をつけます。
> （例：`http://localhost:8000/?demo`）

### 手順C：GitHub Pages で公開する

1. <https://github.com/> でアカウントを作り、ログインします。
2. 右上の「＋」→「New repository」
   - Repository name：`touhou-blackjack`（好きな名前で構いません）
   - **Public** を選びます。（無料プランでは、Public のリポジトリだけが GitHub Pages を使えます）
   - 「Create repository」を押します。
3. 表示された画面の「uploading an existing file」を押し、**この `touhou-blackjack` フォルダの中身**（`index.html`、`css`、`js`、`data` など）をすべてドラッグ＆ドロップして「Commit changes」を押します。
   - 人気投票のExcelファイルは、アップロード不要です。
4. 「Settings」→ 左メニュー「Pages」→ 「Branch」を `main`、フォルダを `/ (root)` にして「Save」を押します。
5. 1〜2分待つと、`https://（ユーザー名）.github.io/touhou-blackjack/` で開けるようになります。
6. スマホでそのURLを開いて遊びます。ルームを作成したら「招待リンクを送る」で、LINEなどに参加用リンクを送れます。

ファイルを書き換えたときは、同じ手順3でもう一度アップロードすると更新されます（反映まで数分かかることがあります）。

### 本番前のチェックリスト

- [ ] スマホ2台以上で、ルーム作成 → 参加 → ゲーム開始 ができる
- [ ] 全員が決定すると、結果が一斉に公開される
- [ ] 同じキャラを選ぶと +0 になり、次のターンで選べなくなる
- [ ] 5ターン目のあとに最終結果が出る
- [ ] 途中でリロードしても、同じゲームに戻れる

## 5. よくある変更のしかた

### 難易度を追加する（Easy / Normal を遊べるようにする）

ルールは難易度ごとに別々に持っています。設定は [js/config.js](js/config.js) の `DIFFICULTY_SETTINGS` にまとまっています。

```js
export const DIFFICULTY_SETTINGS = {
  easy:    { label: 'Easy',    available: false },   // 準備中（Coming Soon）
  normal:  { label: 'Normal',  available: false },
  hard:    { label: 'Hard',    available: true, targetScore: 21,  maxTurns: 5, maxCharacterRank: 50 },
  lunatic: { label: 'Lunatic', available: true, targetScore: 150, maxTurns: 5, maxCharacterRank: null },
};
```

| 項目 | 意味 |
|---|---|
| `available` | `true` なら選べる（PLAY）。`false` のあいだは Coming Soon |
| `targetScore` | 目標値。これを超えたらOUT |
| `maxTurns` | ターン数 |
| `maxCharacterRank` | 使えるキャラクターの範囲。`50` なら人気投票50位以内だけ。`null` なら全員 |

たとえば Easy を「目標100・3ターン・100位以内」で遊べるようにするには、次のように書き換えます。

```js
  easy: { label: 'Easy', available: true, targetScore: 100, maxTurns: 3, maxCharacterRank: 100 },
```

これだけで、待機画面で Easy が選べるようになり、キャラクター一覧・検索・目標値・ターン数・
「遊び方」の説明が、すべてその難易度に合わせて変わります。Hard や Lunatic のコードを書き換える必要はありません。

この3つ**以外**のルールを難易度ごとに変えたいとき（重複の扱い・得点計算・OUTの条件・勝敗判定など）は、
[docs/DESIGN.md](docs/DESIGN.md) の「11. 難易度」に、どこを直せばよいかをまとめてあります。

### 目標値・ターン数・使えるキャラクター・人数を変える

- 難易度ごとの目標値・ターン数・使えるキャラクター：上の `DIFFICULTY_SETTINGS` の数字を書き換えます。
- 人数：同じファイルの `MIN_PLAYERS`（最少人数）と `MAX_PLAYERS`（最大人数）を書き換えます。

### プレイヤー名のデフォルトを変える

[js/config.js](js/config.js) の `DEFAULT_PLAYER_NAME`（いまは「霊夢」）を書き換えます。
名前の欄に最初から入る名前と、入力例の両方が変わります。

### 人気投票のデータを差し替える（次回の投票結果にする など）

1. 新しいExcelファイルを、このフォルダの1つ上（または同じ場所）に置きます。
   - シート名「人気投票結果」、列の見出し「順位」「名前」が必要です。
2. このフォルダで次のコマンドを実行します。

   ```bash
   python tools/convert_excel.py
   ```

   Excelの場所を指定することもできます：`python tools/convert_excel.py "C:\…\結果.xlsx"`
3. `data/characters.json` が作り直されます。
4. 「第22回」という表記は、[index.html](index.html) にあります。

Excelから取り出すのは「順位」と「名前」だけです。ポイントやコメントなどの列は使いません。

### よみがなを追加・修正する

[tools/yomi.json](tools/yomi.json) に「名前 → よみがな」を登録しています。よみがなは次の2つに使われます。

- **検索**：「れいむ」と入力して「博麗 霊夢」を見つける
- **一覧の並び順**：キャラクター一覧を50音順に並べ、「あ」「か」… の見出しをつける

（Excelにはよみがなが無いため、手作業で用意したものです。間違いに気づいたらここを直してください）

```json
"博麗 霊夢": "はくれい れいむ",
"霊烏路 空": "れいうじ うつほ おくう",
```

空白で区切って、あだ名を追加することもできます（並び順には、先頭に書いたよみがなが使われます）。
書き換えたら `python tools/convert_excel.py` を実行すると反映されます。
よみがなが間違っていても、ゲームの点数には影響しません（検索で見つけにくくなる・並ぶ位置がずれるだけです）。

### 色を変える

[css/style.css](css/style.css) の先頭にある `:root { … }` の色を書き換えます。

## 7. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| `index.html` をダブルクリックすると「読み込み中」のまま | `start-local.bat` を使い、`http://localhost:8000/` から開く |
| 黄色い帯「お試しモード」が消えない | `js/firebase-config.js` の `apiKey` が空のまま。保存したか確認し、ページを再読み込みする |
| 「匿名認証が有効になっていません」と出る | 手順A-5（Authentication →「匿名」を有効にする） |
| 「databaseURL がありません」と出る | 手順A-7。`firebase-config.js` に `databaseURL` を入れる |
| 「アクセスが許可されませんでした」と出る | 手順A-4。ルールを貼り付けたあと「公開」を押したか確認する（下の補足も参照） |
| 「通信が切れています」の帯が消えない | 電波・Wi-Fi を確認する。`databaseURL` が正しいか確認する |
| 同じPCで2人目として参加できない（1人目と同じ人になる） | `http://127.0.0.1:8000/`、シークレットウィンドウ、別のブラウザのどれかで開く（手順B-3） |
| スマホで古い画面のまま変わらない | GitHub Pages の反映に数分かかる。ページを再読み込みする |
| 相手が「切断中」のまま戻ってこない | ホストは「未選択の人を待たずに結果を公開」で先に進められる |
| 待機画面から最初の画面に戻りたい | 待機画面の「最初の画面に戻る」を押す（ルームから退出する。通信が切れていても戻れる） |
| Hard で、探しているキャラクターが出てこない | Hard で選べるのは人気投票50位以内の50人だけ。それ以外は一覧にも検索にも出ない |
| 「ゲームが新しくなっています」と出る | ゲームを更新したあと、古い画面のまま開いている。ページを再読み込みする |

**補足：ルールが原因かどうかを切り分けたいとき**

「アクセスが許可されませんでした」が直らないときは、Firebase コンソールの「ルール」を一時的に次の内容にして試してください。
これで動くなら、原因はルールの貼り付け方にあります。

```json
{
  "rules": {
    ".read": "auth != null",
    ".write": "auth != null"
  }
}
```

この状態は、参加者なら誰でもすべてのデータを読み書きできます（他の人の選択も読めてしまいます）。
**確認が終わったら、必ず `database.rules.json` の内容に戻してください。**

## 8. 知っておいてほしいこと（制限）

- **不正対策は「友人同士で遊ぶ」前提です。**
  「相手の選択を見てから自分の選択を決める」ことは、セキュリティルールで防いでいます。
  一方、点数の計算は参加者の端末で行うため、プログラムを改造した端末が不正な点数を書き込むことまでは防げません。
  完全に防ぐにはサーバー側での計算（Firebase の Cloud Functions。有料プランが必要）が必要です。
- **ルームのデータは自動では消えません。**
  1ルームあたり数KBなので、すぐに問題にはなりません。気になったら Firebase コンソールの「データ」で `rooms` と `picks` を削除してください（遊んでいる人がいないときに）。
- **Firebase の無料枠（Sparkプラン）の目安**：同時接続100、保存1GB、転送 月10GB。数ルームが同時に遊ぶ程度なら十分です。最新の条件は Firebase の料金ページで確認してください。
- **イベントなどで大勢が参加するとき**：匿名認証には「同じIPアドレス（同じWi-Fiなど）から新しく参加できるのは、1時間に100人まで」という上限があります。
  一度参加した端末がもう一度遊ぶ分は、数に入りません。
  超えそうなときは、Firebase コンソールの Authentication →「設定」→ 登録の割り当て（Sign-up quota）で、日時を決めて一時的に上限を上げられます。
- **ホストが抜けたとき**：ホスト（ルームを作った人）が待機画面から退出したり、通信が切れたりすると、残っている人のうち最初に入室した人が次のホストになります（その人の画面に「あなたがホストになりました」と出ます）。通信が切れた場合は、検知に1分ほどかかることがあります。ルームを作った人が同じルームに戻ってくると、ホストはその人に戻ります。
- **だれもいなくなったルーム**：全員が退出しても、ルームのデータ自体は消えずに残ります（上の「ルームのデータは自動では消えません」と同じ扱いです）。同じルームIDを入力すれば、また入れます。
- **二次創作としての注意**：公式ゲームと誤認されないよう、画面に「ファン制作（非公式）」と表記しています。原作の画像・音楽は使用していません。画像を追加するときは、権利と東方Projectの二次創作ガイドラインを確認してください。
